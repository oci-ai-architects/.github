# Contributing

Contributions are welcome in every repository of this organization.

## Before you start

- For anything bigger than a typo or a small fix, open an issue first so we can agree on the approach.
- Check the repository's README for how to run its tests or validate a stack.

## How to contribute

1. Fork the repository and create a branch (`fix/<short-name>` or `feat/<short-name>`).
2. Make the change and run the repository's checks locally.
3. Sign off every commit with `git commit -s`. That is the Developer Certificate of Origin: you wrote the change or have the right to submit it, under the repository's licence.
4. Open a pull request and fill in the template. Say what changed and how you tested it.

## AI-assisted changes

Fine, and we use them too. Say so in the pull request, and read what the tool wrote before you submit it. You are responsible for the change.

## Licence

Your contribution is released under the licence of the repository you contribute to. If a repository has no licence file yet, ask in an issue before sending a large change.

## Reviews

A maintainer reviews each pull request. Timing varies; a polite nudge on the pull request is fine.
